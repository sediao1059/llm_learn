# HanLP 与中文语法语义分析（政策匹配链路）

> **一句话**：HanLP 是国产中文 NLP 工具包，一行代码拿到分词/词性/命名实体/依存句法/关键词等全套分析能力。简历场景：**政策计算器核心算法**——基于 HanLP 语法语义分析把非结构化政策文本拆成结构化要素（条件→对象→支持内容），再与企业画像做规则匹配。这是"传统 NLP 工程 + 业务规则"的经典落地，面试要能讲清整条链路。

## 1. HanLP 能力地图

| 能力 | 输出示例（政策文本场景） |
|---|---|
| 分词 + 词性标注 | 对/苏州工业园区/注册/的/制造业/企业/给予/补贴 |
| 命名实体识别（NER） | 地点=苏州工业园区、金额=200万元、行业=制造业 |
| 依存句法分析 | "给予"←核心动词；"企业"是对象；"补贴"是内容 |
| 关键词/摘要提取 | 政策主题词抽取 |
| 语义角色标注（SRL） | 施事/受事/条件 等论元结构 |

版本：HanLP 1.x 经典版（Java/统计模型+词典，工业稳定）→ HanLP 2.x（深度学习/Torch，精度更高）——简历链路用 1.x 起家、2.x 升级都合理。

## 2. 政策匹配核心链路（简历项目完整展开）

```
政策原文（数千条）                     企业画像（工商/税务/资质数据）
    │                                     │
    ▼ HanLP 分析                          ▼ 结构化标签（自动化标签体系）
① 分词+NER：抽实体（区域/行业/规模/成立年限/资质/金额）
    ▼
② 依存句法+规则：识别条件结构
   "对【注册在园区的】(条件)【制造业企业】(对象)【给予最高200万补贴】(支持内容)"
    ▼
③ 要素入库：政策 → 结构化规则（条件表达式 + 标签体系）
    ▼
④ 匹配计算：企业标签 vs 政策条件（规则引擎 + 腾讯词向量语义相似度兜底模糊匹配）
    ▼
⑤ 排序输出：可申报政策列表 + 匹配理由（每条可解释）
```

关键设计点：
- **自动化标签体系**：政策侧与企业侧用同一套标签本体（行业/规模/区域/资质），匹配才有共同语言——这是"政策计算器"的真正地基；
- **语义兜底**：字面不等但语义相近的匹配（"智能制造"≈"高端装备"）用词向量相似度补规则之 rigid；
- **可解释性**：输出"为什么匹配"（命中了哪些条件），政务交付刚需；
- 演进（简历原话）：2024 年基于 GLM-4-9B LoRA 微调做政策分类与信息提取，把 ②③ 步升级为模型化抽取——**规则时代可解释、模型时代泛化强**，两者结合（模型抽 + 规则校验）是当前最优解。

## 3. 传统 NLP 工具横向认知

- HanLP vs jieba：jieba 只有分词（轻量）；HanLP 全家桶（句法语义深）；
- vs LLM 抽取：LLM 少样本即可定义新抽取消任务，但高并发场景成本高；HanLP/小模型毫秒级——生产上常见"LLM 冷启动造标注数据 → 小模型/BERT 上线"。

## 4. 高频面试题

1. 政策匹配怎么处理"模糊表述"？（词向量语义相似度 + 人工确认阈值带 + 标签体系归一）
2. 为什么不直接用大模型抽取全部政策？（成本/时延/批量吞吐 + 可控性；但可用它做数据增强与冷启动）
3. NER 效果不好怎么优化？（领域词典注入、领域标注微调、规则后处理、错误分析回流）

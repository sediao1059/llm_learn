# 大模型幻觉抑制

> **一句话**：幻觉 = 模型生成**看似合理但与事实/输入不符**的内容。根因是它的训练目标只是"预测下一个最像的词"，没有任何真实性约束。工程上无法根除、只能**分层压制**：事前给依据（RAG/工具/元数据）、事中加约束（低温/结构化/提示限定）、事后做校验（执行/溯源/自检）。简历里问数、Function Call、RAG 三处"减少幻觉"的实践，串起来就是一套完整的分层防御答案。

## 1. 幻觉的分类与成因

- **事实性幻觉（Factuality）**：与世界不符——编造政策条款、不存在的论文；
- **忠实性幻觉（Faithfulness）**：与给定输入/检索材料不符——材料里没有却硬答、曲解表格数字；
- 成因（面试简答版）：
  1. 训练目标 = 下一词概率最大化，"流畅"优先于"真实"；
  2. 训练数据本身有错且过时，模型知识有边界但**不知道自己不知道**；
  3. 解码随机性（温度采样）放大编造；
  4. 提示词诱导（强行要求回答没有依据的问题，模型宁可编）。

## 2. 分层防御体系（核心框架）

```
┌─ 事前（给依据）────────────────────────────┐
│ RAG 检索真实材料 | 工具调用查实时数据         │
│ 元数据/schema 对齐 | 提示词限定"只依据材料回答"│
│ 允许说"不知道"：无依据时输出兜底话术/转人工    │
├─ 事中（加约束）────────────────────────────┤
│ 低 temperature | 结构化输出（JSON Schema）    │
│ 引用标记：每个论断绑定材料编号               │
├─ 事后（做校验）────────────────────────────┤
│ 可执行的先执行（SQL/计算交给代码）            │
│ 结果合理性校验（量级/行数/类型）              │
│ 溯源校验：答案与引用片段一致性比对             │
│ SelfCheckGPT：多次采样对比，分歧大→疑似幻觉    │
│ 人工反馈回流（点踩日志→badcase 池→优化）      │
└───────────────────────────────────────────┘
```

## 3. 场景化落地（把简历三处实践串成体系答）

- **智能问数**：数字必须来自 SQL 执行结果（模型禁止心算）、schema/值先检索对齐、执行报错回传重试 → 事实性幻觉压制；
- **Function Call 工具化**：订单状态/政策条款这类事实问题强制走工具，模型只负责组织语言 → 从根上绕开记忆幻觉；
- **RAG + 引用**：只依据材料回答 + 引用编号，忠实性幻觉可查可溯；检索为空时明确说"知识库未覆盖"；
- **正负样本迭代**：badcase（幻觉样本）作为负样本进入评测集与微调数据，模型层面也变好。

## 4. 评测（怎么证明幻觉变少了）

- 构造幻觉评测集：无答案问题（看是否老实说不知道）、易编造实体问题、材料冲突问题；
- 指标：忠实度（Faithfulness，答案是否被材料支持）、事实准确率、拒答率/误拒率平衡；
- 自动化：LLM-as-Judge 按"答案-引用"对齐打分；关键场景人工抽检。

## 5. 高频面试题

1. 幻觉能彻底解决吗？为什么？（不能，概率生成机制决定；工程目标是可控可发现可兜底）
2. RAG 之后为什么还有幻觉？（检索错了、材料矛盾、生成不忠实——所以要分段评测+引用约束+忠实度校验）
3. 温度调 0 就没幻觉了吗？（只是降低采样随机性，知识性编造依旧）
4. 怎么让模型"知道自己不知道"？（提示允许拒答 + 无依据兜底策略 + 置信度/自检采样）

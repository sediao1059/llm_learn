# 内容编写与界面文案规范

> 本规范由项目实践沉淀而来，核心两条：**学习者既有新手也有老手，一切标签与功能必须同时服务两类人；解释一律用直白的话**。适用于：写学习笔记、定标签/难度/路线、开发图谱功能、写任何界面文案。

## 1. 双受众原则（新手 & 老手）

每个知识点组织维度和每个功能，都要过一遍这两问：

| 问题 | 新手视角 | 老手视角 |
|---|---|---|
| 从哪开始？ | 有明确入口：路线视图「① 打底线」+ 空面板引导文案 | 力导向/分层视图总览，自由进入 |
| 怎么过滤？ | 难度筛选只留「入门+进阶」，跳过深入 | 只看「深入」查漏补缺；按层/标签精确定位 |
| 解释到什么程度？ | 术语首次出现必须"翻译"成大白话，先讲是什么再讲为什么 | 原理推导、参数量估算、面试高频题给足 |
| 出错了怎么办？ | 每步有引导（下一步学什么、按钮干嘛的） | 可直接跳过引导，操作路径不超过两步 |

**新功能上线前 checklist**：
- [ ] 新手能看懂怎么用吗？（hover 提示 / 帮助弹窗条目）
- [ ] 老手有增量价值吗？（不是纯装饰）
- [ ] 状态可保留、可一键还原吗？（筛选/视图选择要持久化，且有清除入口）

## 2. 大白话原则（直白的话解释）

1. **一句话摘要强制**：每篇笔记正文第一个 blockquote 必须是 `> **一句话**：…`，构建时自动提取到图谱 tooltip 和笔记面板顶部。写法要求：
   - 外行能一次听懂，不许出现未解释的缩写/黑话；
   - 用比喻优先（"KV Cache 就是模型做题时的草稿纸"）；
   - 公式、术语、精确表述放正文，摘要只说人话。
   - 构建时缺摘要会告警（见 §6）。
2. **术语首现必须翻译**：`PagedAttention（把缓存像操作系统内存一样分页管理）`。之后再出现可直接用。
3. **表达优先级**：图（ASCII/表）> 表格 > 列表 > 长段落；具体例子 > 抽象描述。
4. **界面文案规则**：
   - 按钮/筛选用动宾短语说人话：「只看入门难度」而不是「难度 facet 过滤」；「放大查看」而不是「全屏化阅读容器」；
   - 每个控件必须带大白话 hover 提示（title）；
   - 新功能必须同步更新「❓ 使用说明」弹窗（大白话版）；
   - 空状态要给行动指引（"不知道从哪学起？切到路线视图"）。
5. **自测标准**：把解释念给一个刚入行的人听，能一次听懂就合格；他反问"这是什么意思"就重写。

## 3. 笔记结构模板（固定格式）

```markdown
---
（frontmatter，字段见 §4）
---

# 标题

> **一句话**：（大白话，必填）

## 1. 背景 / 是什么（为什么会有这个东西）
## 2. 核心原理（图/表优先，术语首现翻译）
## 3. 实践 / 简历场景对齐（能落到自己项目的写法）
## 4. 高频面试题（2-5 道，附答题要点）
## 5. 衍生学习（未来坑位，对应 todo 节点或正文条目）
## 6. 参考资料（与 frontmatter sources 一致）
```

## 4. frontmatter 字段规范

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 建议 | 节点唯一 ID，缺省用文件名 |
| `title` | ✅ | 图谱节点显示名 |
| `category` | ✅ | 维度A·领域分类（决定默认节点颜色） |
| `layer` | ✅ | 维度B·技术层次：`L1-算法底层 / L2-大模型底层 / L3-应用工程层 / L4-业务应用层` |
| `path` | 按需 | 维度D·学习路线，格式 `路线号.步骤号`（如 `1.2`），只把有前置依赖顺序的知识点排进路线 |
| `difficulty` | ✅ | 维度E·难度：`入门 / 进阶 / 深入`，判据见 §5 |
| `status` | ✅ | `learned`（已写完）/ `todo`（衍生学习坑位，图谱虚线显示） |
| `tags` | 建议 | 搜索与筛选用，中文优先、控制在 5 个内 |
| `links` | 建议 | 关联知识点 id 列表（生成连线），按知识依赖写 |
| `sources` | 建议 | 参考资料，`- [标题](URL)` 列表 |

## 5. 元数据标注判据（避免随手标）

- **difficulty**：
  - `入门`：不需要其他前置知识，或纯概念/工具使用（如提示词工程、RAG 概念、产品案例）；
  - `进阶`：需要打底线知识（懂 Transformer/训练循环）才能真懂（如 LoRA、GraphRAG、vLLM 调优）；
  - `深入`：涉及数学推导、多卡/系统级工程、或研究领域（如 RLHF、量化算法、投机解码）。
- **path**：只在"步骤间存在真实的前置关系"时排入同一条线；新增主线用新的路线号，并在 build.mjs 的 `ROUTE_NAMES` 登记名称。
- **layer**：按"离业务距离"分层，不按难度（一个 L1 节点可以比 L4 难）。
- **links**：优先写"学 A 之前该会 B"的依赖边，其次是"对比/配套"关系。

## 6. 可执行检查（构建期）

`graph/build.mjs` 在以下情况输出告警（exit code 1）：
- 正文缺少「> 一句话」大白话摘要；
- 缺 `layer` / `difficulty`；
- `links` 指向不存在的知识点；
- `path` 格式不合法；id 重复。

## 7. 修改流程

写/改笔记 → `cd graph && npm run build`（看告警清零）→ 刷新页面确认图谱 → git 提交。功能开发另见根目录 `AGENTS.md`。
